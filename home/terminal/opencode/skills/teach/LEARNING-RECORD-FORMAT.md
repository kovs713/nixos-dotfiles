# Learning record format

Write only when saving is requested or agreed for this workspace. Preserve existing `learning-records/NNNN-slug.md` conventions; create the directory only for the first useful record. Scan existing numbers and use the next unused number; never overwrite another record.

Record evidence that changes the next lesson or practice choice, not every turn. A partial session, a request to skip, or an assisted solution can leave a useful resume point without establishing understanding.

## Template

```md
# {Topic or insight}

Date: {YYYY-MM-DD}
Goal: {The agreed outcome}

## Knowledge
{Only useful subject facts, assumptions, and their connections: premises → conclusion. Cite a source for a doubtful or version-sensitive claim. Omit if already captured in the user's notes.}

## Evidence
- {Task and observed answer/reasoning; distinguish self-report from demonstrated application.}
- {Assistance: none, attention nudge, named principle, worked step, solution shown, or skipped.}

## Resume
{First unresolved prerequisite or next target; note any fresh retest still needed.}
```

Keep it short; omit empty sections. A bare teacher explanation belongs in subject notes, not evidence that the user knows it. A correct immediate check does not prove long-term retention; a stated familiarity is self-report until checked. Record a repaired misconception as repaired only when a fresh application supports that conclusion.

For a changed goal, update `MISSION.md` only with confirmation. When new evidence contradicts an earlier record, preserve the history and mark it `Status: superseded by NNNN-slug.md`, linking the actual replacement. Existing short records remain valid; qualify their evidence when resuming rather than rewriting the archive.
